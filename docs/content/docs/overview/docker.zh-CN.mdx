# Docker 部署

如果你希望在自己的机器或服务器上运行项目，可以直接使用 Docker Compose。

## 运行完整服务栈

```bash
git clone git@github.com:basketikun/infinite-canvas.git
cd infinite-canvas
cp .env.example .env
# 修改 .env 中的数据库、MinIO、S3 与 Better Auth 密钥
docker compose up -d --build
```

启动后访问：

```text
http://localhost:3000
```

## 当前生产域名

当前生产入口使用 `https://canvas.zgonline.top`，域名应由宿主机 Nginx 反向代理到仅监听本机的应用端口。生产环境的 `.env` 至少覆盖以下配置：

```dotenv
APP_BIND_HOST=127.0.0.1
APP_PORT=3000
APP_ORIGINS=https://canvas.zgonline.top
BETTER_AUTH_URL=https://canvas.zgonline.top
POSTGRES_DATA_PATH=/data/infinite-canvas/postgres
MINIO_DATA_PATH=/data/infinite-canvas/minio
BACKUP_ROOT=/data/backups/infinite-canvas
```

Sub2API 尚未提供 OIDC Provider 时，`SUB2API_OIDC_DISCOVERY_URL`、`SUB2API_CLIENT_ID` 和 `SUB2API_CLIENT_SECRET` 必须保持为空；Provider 上线并注册回调地址后再同时配置。

## 生产 CI/CD 约束

PR 与 `main` push 会通过 `.github/workflows/ci.yml` 执行 Web、Server、Docs、插件、Compose 和 Shell 检查。`main` 检查成功后发布 `ghcr.io/<owner>/<repository>-web:<commit-sha>` 与 `ghcr.io/<owner>/<repository>-api:<commit-sha>`，再经 GitHub `production` Environment 部署。

生产 SSH Key 由 `deploy/github-actions-entrypoint.sh` 限制，只接受 `probe` 与白名单仓库的 commit。部署包里的 entrypoint 必须与服务器已审核版本完全一致，entrypoint 升级由管理员手工安装，不能由 CI 自更新。`deploy/deploy-production.sh` 拉取不可变镜像，在 migration 前验证 PostgreSQL/MinIO 备份，检查内网与公网健康状态，失败时恢复旧源码和旧镜像 tag。数据库 migration 必须保持向后兼容；不兼容的 schema 降级只能在维护窗口中使用已验证备份人工执行。

版本 tag 会为 Web/API 发布多架构镜像，同时保留 `v*` 与 commit-SHA tag；生产仍只部署 CI 验证过的 commit-SHA，不使用可变 tag。

在 GitHub 新建名为 `production` 的 Environment，配置 `PRODUCTION_URL`、`PRODUCTION_SSH_HOST`、`PRODUCTION_SSH_PORT`、`PRODUCTION_SSH_USER` 变量，并添加 `PRODUCTION_SSH_PRIVATE_KEY` 与经过校验的服务器 Host Key 行 `PRODUCTION_SSH_KNOWN_HOSTS`。服务器把 `deploy/github-actions-entrypoint.sh` 安装为 `/usr/local/sbin/infinite-canvas-github-actions`，把 `deploy/infinite-canvas-deploy.conf.example` 以 root 所有、`0600` 权限安装为 `/etc/infinite-canvas-deploy.conf`；对应公钥在 `authorized_keys` 中必须加 `restrict,command="/usr/local/sbin/infinite-canvas-github-actions"`。不要复用日常管理员 SSH Key。

## 本地构建镜像

如果需要基于当前源码构建镜像：

```bash
docker compose -f docker-compose.local.yml up -d --build
```

## 文档站镜像

文档站位于 `docs/` 目录，按带服务端能力的 Next.js standalone 应用单独构建，不打进主应用镜像。

使用发布镜像：

```bash
cd docs
docker compose up -d
```

基于当前源码本地构建：

```bash
cd docs
docker compose -f docker-compose.local.yml up -d --build
```

## 数据说明

主应用由 Nginx 前端、Fastify API、独立 PostgreSQL 和私有 MinIO 组成。账户、Session 与导入的数据清单保存在 PostgreSQL，媒体文件保存在 MinIO；PostgreSQL 和 MinIO 默认都不映射宿主机端口。

用户登录后，应用会检测当前浏览器的画布、我的素材和生图/视频记录，确认后执行一次性导入。IndexedDB 不会被删除，仍是当前设备的工作缓存；后续编辑的持续云同步尚未实现。AI API Key、Base URL、WebDAV/Agent 凭据、插件代码和提示词缓存不会上传。

## 备份与恢复验证

生产环境可执行：

```bash
./deploy/backup.sh
./deploy/verify-backup.sh /data/backups/infinite-canvas/<backup-id>
```

备份包含 PostgreSQL custom dump、MinIO 对象镜像和 SHA-256 清单。验证脚本会启动独立临时 PostgreSQL，真实恢复后核对表和对象数量，不会改写生产数据库。`deploy/systemd/` 提供每日 timer；服务器内备份仍应再复制到异地存储。

## 统计分析（可选）

项目**默认不接入任何统计**：不设置下列环境变量时，页面不会加载任何统计脚本，也不会发送任何外部请求。你在自己的部署上想查看流量时，设置对应环境变量即可，无需修改代码或重新构建镜像——镜像启动时会据此生成运行期配置。

统计按「每家一个独立变量」配置：**填了谁就启用谁，可同时启用多家**（例如 GA4 + 百度一起开）。仅支持 GA4 与百度，两者都只接受 ID，脚本地址由代码固定拼接，不接受任意脚本地址或内联 JS。

| 变量 | 说明 |
| --- | --- |
| `ANALYTICS_GA4_ID` | Google Analytics 4 衡量 ID（`G-XXXX`） |
| `ANALYTICS_BAIDU_ID` | 百度统计站点 ID（`hm.js?` 后面那串 hash） |

在生产 `.env` 中配置，下例同时启用 GA4 与百度：

```dotenv
ANALYTICS_GA4_ID=G-XXXXXXXXXX
ANALYTICS_BAIDU_ID=e8263761cc5c32f5f7a855b8203b965a
```

或使用 `docker run`：

```bash
docker run -d -p 3000:3000 \
  -e ANALYTICS_GA4_ID=G-XXXXXXXXXX \
  -e ANALYTICS_BAIDU_ID=e8263761cc5c32f5f7a855b8203b965a \
  infinite-canvas-web:local
```

单页应用的路由切换会自动向所有已启用的统计上报 pageview。

<Callout type="warn">
请只在你自己的站点上配置统计 ID，不要把 ID 提交进仓库；fork 或自托管本项目的用户默认不会产生任何统计。
</Callout>
